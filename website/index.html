04

三条命令，建起一个高可用共享。

装好 Haify、注册好服务器之后，从空盘到一个坏一台也不断的 NFS 共享。

root@node1 — haify
# 1 · 用三台服务器的空盘建存储池
haify pool create --name pool0 --type lvm-thin \
  --nodes node1,node2,node3 --devices /dev/sdb

# 2 · 建一个 100G 的卷，自动放到最空的两台上
haify resource create --name data --port 7001 --size 100G --pool pool0

# 3 · 导出为高可用 NFS
haify gateway nfs create --resource data \
  --service-ip 192.168.1.200/24 --export-path /data

# 就绪 —— 客户端始终访问同一个地址，服务器坏了约 70 秒自动接管
mount -t nfs 192.168.1.200:/data /mnt

05

常见问题

关于 Haify 能做什么、跑在哪、坏了怎么办的直接回答。

Haify 是什么？

Haify 是一套开源的软件定义存储：把你自己 Linux 服务器上的硬盘变成共享存储，给文件、虚拟机、容器和数据库用。每份数据同时写在多台服务器上，坏一台机器不丢数据，一分钟左右自动接管。底层用的是 Linux 内核里成熟的 DRBD 复制。

Haify 能跑在哪些平台上？

CPU 支持 x86_64、aarch64（含鲲鹏、飞腾）与 loongarch64（龙芯）；操作系统支持 Debian、Ubuntu、RHEL 系以及麒麟、统信 UOS。可在完全离线的环境中部署。

Haify 和 Ceph、LINSTOR 有什么区别？

与 Ceph 相比更轻：一个控制器管理全部节点，不用维护 MON/OSD/MGR 等多种守护进程。与 LINSTOR 相比，存储节点上不需要常驻代理进程。

服务器坏了会怎样？多久恢复？

存储和跑在上面的服务，连同对外访问的地址，会自动转到另一台健康的服务器上，大约 70 秒；客户端始终访问同一个地址，不用改配置。仲裁机制防止两台服务器同时写同一份数据（脑裂）。

支持哪些虚拟化平台？

Proxmox VE（存储插件，PVE 网页里带 Haify 面板）、普通 KVM/libvirt，以及 OpenStack（Cinder 驱动，Horizon 里带面板）。三者都支持虚拟机热迁移；宿主机坏了，虚拟机能带着数据在另一台上重新启动。

Haify 支持 Kubernetes 吗？

支持，OpenShift 也能用。持久卷支持快照、克隆、扩容和加密；不用重建就能改副本数和限速；快照可以存到集群外，在另一个集群里恢复。节点断电后大约半分钟，Pod 带着数据在另一台机器上跑起来，不用等 Kubernetes 默认的 5 分钟。

会丢数据吗？

写入返回时，数据已经在多台服务器上，所以坏一台不丢数据。另外可以定时备份到 S3、SMB 或 WebDAV，或在另一个机房保留一份实时副本，整个集群没了也能恢复。
